# MotionForge

一个以手动操作为主的 **2D 骨骼动作编辑器**，用于制作单张姿势和完整动作序列。

通过 IK 调整四肢、编排关键姿势的持续时间、预览动作并导出图片。制作好的动作图可由用户手动上传到其他 AI 工具进行生图。

> 当前 M0–M3 已完成：支持骨架编辑、姿势库、自动保存、工程备份、关键姿势时间轴与保持式播放。M4 图片导出已开放，参考图与辅助编辑仍待完成。

## 本地运行

建议使用 Node.js 22.12+，本次开发环境为 Windows、Node.js 25.2.1、npm 11.6.2。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址（默认 `http://127.0.0.1:5173`）。

拖动手腕、脚踝的大圆点，通过 IK 带动四肢；拖动肘、膝、头部、手脚等骨段末端的小圆点直接旋转对应骨段。拖动金色根节点移动角色。骨长保持不变，IK 目标不可达时以金色虚线显示实际末端与目标的偏差。从骨骼树或画布选择骨段，也可在右侧输入局部旋转角度，按 Enter 或移开焦点提交。滚轮缩放，点击“适配画布”恢复视图。使用工具栏或 Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y 撤销、重做，输入框内保留原生文本编辑快捷键。一次拖动只形成一条历史，拖动中按 Esc 取消。

选中上臂、前臂、大腿或小腿后，右侧可切换 IK/FK，切换不改变姿势。IK 模式下可点击“翻转弯曲方向”，也可将画布上的金色方向柄拖到肢体另一侧。FK 模式下拖动腕/踝点只旋转下段骨骼。按住空格或鼠标中键拖动画布进行平移。

右侧“身体朝向”提供正面、朝左侧身、朝右侧身，以及 −90°～90° 的转身角度。肩部和髋部随转身收窄，手脚默认方向、头部朝向标记和前后显示顺序随之调整；四肢骨长和已编辑的局部旋转保留。这是当前姿势的 2D 侧身表达，不是旋转 3D 模型或全工程缩放。重置姿势保留身体朝向，点击“正面”恢复正面。两侧关节点重叠时，先从骨骼树选择骨骼，该骨骼拖动点会优先响应。

简易假人默认显示，用椭圆头部、胸腔/骨盆轮廓、渐细四肢与关节连接表现人体体积，并实时跟随骨骼。肩部连接块跟随肩骨延伸，正面肩髋关节均位于躯干前，侧面按远近关系遮挡。右下角“假人”和“骨架线”可分别开关，关节点始终保留以继续编辑；开关是临时视图设置，不改动姿势数据。当前为几何部件绑定，不支持上传图片蒙皮或网格权重编辑。

选中四肢骨骼可启用关节限制，填写相对静止姿势的最小、最大角度。限制是项目级设置，会调整所有超出范围的姿势，可整体撤销。受限 IK 在允许范围内寻找更接近目标的解，属性区显示实际目标偏差；重置姿势也遵守限制。

**工程在编辑提交后自动保存到本机浏览器，刷新会恢复上次工程。** 顶部显示保存状态，失败时可重试或直接下载备份。姿势库支持命名保存、骨架缩略图、重命名、加载、删除及 JSON 导入导出；加载后编辑不影响已保存资产，相关操作可撤销。顶部“保存备份”下载 `.motionforge` 工程，“打开工程”校验并载入为本机副本，“新建工程”先尝试保存当前工程。保存失败时离开工程会要求确认；关闭页面前尚未完成保存也会触发浏览器提醒。自动保存绑定浏览器及访问地址，迁移环境或清理站点数据前请下载备份。当前不支持多标签协同编辑。序列编排已开放，图片导出已开放，参考图与其他辅助编辑仍在开发。

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

核心测试覆盖数据校验、FK、坐标转换、命令历史、状态隔离和 3/2/4 帧采样。浏览器测试覆盖属性编辑、撤销重做与整次根节点拖动。

也可使用已安装的 Chrome 执行浏览器测试（PowerShell）：`$env:PLAYWRIGHT_CHANNEL='chrome'; npm run test:e2e`。当前图片导出增量验收覆盖 89 项核心测试和 25 条浏览器流程，包含姿势隔离、刷新恢复、干净环境导入、损坏文件保护和存储失败备份。阶段记录见 [M0 开发记录](doc/开发记录-M0.md)、[M1 开发记录](doc/开发记录-M1.md)、[M2 开发记录](doc/开发记录-M2.md) 和 [M3 开发记录](doc/开发记录-M3.md)。

## 核心功能规划

- **2D 骨骼编辑**：默认人体骨架，支持手脚 IK、骨骼 FK 旋转、弯曲方向调整和根节点移动。
- **单姿势保存与读取**：保存可继续编辑的骨骼数据，建立可复用的姿势库。
- **关键姿势时间轴**：添加、复制、排序和删除关键姿势，为每段设置持续帧数。
- **动作预览**：播放、暂停、循环、逐帧查看及前后关键姿势洋葱皮。
- **工程保存**：本地自动保存、工程备份与恢复、单姿势 JSON 导入和导出。
- **动作图导出**：当前姿势 PNG、关键姿势图包和实际播放帧图包，支持透明或纯色背景。

## 关键姿势与持续帧数

一个关键姿势可以占用多个实际播放帧。首版采用保持式播放，不自动补间。

| 关键姿势 | 持续帧数 | 实际播放帧 |
| --- | --- | --- |
| A：准备 | 3 | 1–3 |
| B：出手 | 2 | 4–5 |
| C：收势 | 4 | 6–9 |

以上动作包含 **3 个关键姿势、9 个播放帧**；在 12 FPS 下总时长为 **0.75 秒**。

播放顺序为 `A A A B B C C C C`。保存时保留每段姿势与持续帧数，无需手动复制重复帧。

## 使用流程规划

1. 创建工程，通过骨骼和 IK 控制点摆出姿势。
2. 将姿势保存到姿势库，或加入动作序列。
3. 调整关键姿势顺序及持续帧数，播放检查动作节奏。
4. 保存可编辑工程，导出动作图或帧图片包。
5. 如需生图，自行将导出的图片上传到其他 AI 工具。

本项目不提供 AI 接口、自动上传、提示词编辑或生成任务。保存的骨骼数据用于继续编辑，导出的图片用于外部手动使用。

## 技术方案

采用浏览器本地运行的单页应用，无需业务后端。依赖通过 `package-lock.json` 锁定。

| 模块 | 计划选型 |
| --- | --- |
| 界面与构建 | React、TypeScript、Vite |
| 2D 画布 | Konva、react-konva |
| 骨骼与动作核心 | 纯 TypeScript，包含 FK、两段 IK 和帧采样 |
| 状态管理 | Zustand |
| 本地存储 | IndexedDB、Dexie |
| 数据校验 | Zod |
| 文件打包 | JSZip |
| 验证 | Vitest、Playwright |

源码按 `src/core`、`src/editor`、`src/persistence`、`src/export` 划分；核心数学和数据层不依赖 React。Dexie 已用于工程自动保存，JSZip 已用于工程备份；图片导出已支持当前姿势、关键姿势及实际播放帧图包。

## 时间轴操作

点击“新建动作”，再“添加当前姿势”；空动作使用独立草稿，已有动作复制当前段姿势并插在该段后。也可从姿势库点击“加入动作”，插入独立快照。通过“编辑目标”切换草稿或动作，草稿始终保留。

点击姿势块选中该段，在右侧编辑骨架会修改整段；上方可重命名、复制、删除、另存为姿势。输入“持续帧数”并按 Enter，或拖动块右边缘调整时长；拖动块到另一块上改变顺序。横向滚动查看长动作，块宽与帧数成正比。

点击/拖动帧刻度移动播放头，聚焦刻度后可用左右方向键逐帧、Home/End 跳到首尾；工具栏提供逐帧、前后关键姿势跳转、播放/暂停和循环开关。非循环播放停在末帧，末帧再次播放从开头开始；改变 FPS 或切到后台会暂停。播放期间锁定骨架和序列编辑。洋葱皮显示前一段蓝色、后一段金色骨架，可调透明度，播放时隐藏。

单动作最多 300 个关键姿势、3000 个播放帧。所有动作编辑参与撤销和自动保存；播放头、动作选择、洋葱皮属于临时界面状态，重新打开默认显示独立草稿。当前没有自动补间。

## 导出动作图

点击顶部“导出图片”，选择当前姿势 PNG、关键姿势图包或实际播放帧图包。可选透明或纯色背景、假人和骨架线；预览显示实际输出，图包预览为动作第一段。

图片按工程画布尺寸绘制，不受编辑视口缩放和平移影响。不包含墙地背景、网格、选择框、洋葱皮、操作手柄和参考图。图包使用 `key_0001.png` 或 `frame_0001.png` 连续编号，附带 `manifest.json`，记录尺寸、FPS、背景、图片顺序、帧区间及持续帧数。

导出期间可查看进度并取消；不会修改工程。单张最多 16×1024×1024 像素，整包最多 64×1024×1024 像素，累计 PNG 数据最多 128 MiB，超限时选择较短动作或关键姿势图包。导出功能详情见 [M4 开发记录](doc/开发记录-M4.md)。
