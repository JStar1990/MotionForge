# MotionForge 2D 动作编辑器开发计划

版本：v0.1 · 2026-10-26

依据：[2D 动作编辑器方案](./2D动作编辑器方案.md) v0.2。

当前状态：M0–M3 已实现并验收，已提供骨架编辑、姿势库、自动保存、工程备份及时间轴播放。M4–M5 尚待完成；详见 [M0 开发记录](./开发记录-M0.md) 和 [M1 开发记录](./开发记录-M1.md)。复选框记录实际完成情况。

## 1. 交付目标

交付可在本地浏览器使用的单角色 2D 动作编辑器，完成以下闭环：

**手动摆姿势 → 保存和读取骨骼数据 → 编排关键姿势与持续帧数 → 播放预览 → 导出动作图。**

导出的图片由用户手动上传到其他 AI 工具。本计划不包含任何 AI 接口、自动上传、生成任务、账号或业务后端。

保留现有技术选型：React、TypeScript、Vite、Konva/react-konva、Zustand、Dexie、Zod、JSZip；验证采用 Vitest 和 Playwright。初始化时核对兼容版本并提交依赖锁文件，不在计划阶段固定未经验证的版本号。

## 2. 阶段与依赖

执行顺序为 **M0 → M1 → M2 → M3 → M4 → M5**。每阶段先完成可操作的闭环并通过对应验收，再进入下一阶段。

| 阶段 | 交付结果 | 主要依赖 |
| --- | --- | --- |
| M0 工程与数据基础 | 可以启动的编辑器框架、统一数据和命令模型 | 无 |
| M1 骨架编辑 | 可以稳定操作的 2D 人体骨架与 IK | M0 数据与坐标约定 |
| M2 姿势与工程保存 | 姿势可复用，工程可关闭、读取并继续编辑 | M1 姿势数据稳定 |
| M3 时间轴与播放 | 关键姿势可按持续帧数组成完整动作 | M2 保存体系 |
| M4 图片导出与辅助编辑 | 可以导出并手动用于外部工具的动作图 | M3 统一帧采样 |
| M5 集成验收 | 可交付的首版、示例工程和使用说明 | M0–M4 完成 |

M1 是操作原型；M3 是完整动作编辑版本；M5 才是本计划的首版完成点。没有指定截止日期，因此按阶段验收推进，不将未经实测的工期写成承诺。

## 3. M0：工程与数据基础

### 任务

- [x] M0-01 初始化 React + TypeScript + Vite 工程，建立开发、构建、类型检查和测试命令。
- [x] M0-02 按方案建立 `core`、`editor`、`persistence`、`export` 模块，配置代码规范与依赖锁文件。
- [x] M0-03 实现 Rig、PoseSnapshot、PoseAsset、KeyPose、Clip、Project 类型与运行时校验。
- [x] M0-04 制作默认人体骨架数据，明确左右命名、连接位置、骨长、静止角和四条 IK 链。
- [x] M0-05 实现工程状态、临时 UI 状态、播放状态的分离；建立编辑命令、撤销与重做机制。
- [x] M0-06 搭建顶部工具栏、左侧资源区、中央画布、右侧属性区、底部时间轴布局及空状态。
- [x] M0-07 建立固定测试数据：默认姿势、不同长度的两段骨骼、A×3/B×2/C×4 序列和损坏工程。

### 实现约定

- 坐标采用项目像素，X 向右、Y 向下；角度存弧度、显示角度。
- 默认画布 1024×1024，12 FPS，新关键姿势持续 2 帧。
- 关键姿势保存完整快照，开始帧由顺序和持续帧数计算。
- 数据模型在方案草案上补充独立姿势草稿，使草稿与序列切换、工程恢复都有明确存储位置；选择、视口和播放状态不写入姿势数据。
- 一次拖动是一条命令；只在提交时进入历史和触发保存，临时预览不产生大量历史记录。

### 验收

应用可启动和构建；默认工程通过数据校验；无效骨长、循环骨架、重复 ID 和非整数时长被拒绝；编辑命令可以撤销和重做。

## 4. M1：骨架编辑

### 任务

- [x] M1-01 实现 FK 世界变换计算及屏幕/项目坐标转换。
- [x] M1-02 渲染骨段、关节、左右颜色、名称提示、骨骼树与选择状态。
- [x] M1-03 实现画布缩放、平移、适配画布和根节点拖动。
- [x] M1-04 实现 FK 旋转及位置/角度属性输入，支持头部、躯干、手脚末端朝向调整。
- [x] M1-05 实现四肢解析式两段 IK、弯曲侧切换和肘膝方向控制柄。
- [x] M1-06 实现不可达目标处理、角度限制和受限结果反馈，处理零距离、折叠、伸直等边界。
- [x] M1-07 实现 IK/FK 切换、重置姿势及撤销重做；切换控制方式不改变当前可见姿势。
- [x] M1-08 为 FK、IK、约束和坐标转换补充有针对性的数学测试。

### 验收

可以手动摆出站立、抬手、弓步三种姿势；拖动手脚时骨长不变；移动和缩放视口后仍可准确操作；极限输入不会产生 NaN 或无穷大；一次撤销恢复整次拖动前的状态。

先在此阶段解决 IK 稳定性，不将算法问题留到界面打磨时处理。

M1 已验收：支持四肢 IK/FK 切换、翻转按钮与方向柄、关节限制和误差反馈、空格/中键平移，所有姿势编辑可撤销。51 项核心测试、12 条浏览器流程通过，生产构建通过。已通过实际画布操作检查站立、抬手、弓步姿势；详细结果见 M1 开发记录。性能目标仍留待 M5 测量。

侧身反馈增量已完成：当前姿势增加正面/左右侧身预设和连续转身角度，肩髋投影收窄，四肢长度保持，支持侧身后 IK/FK 与重叠点选择。当前测试总计 59 项核心测试、13 条浏览器流程通过；详见 M1 开发记录。M4 的项目级比例与自由显示顺序仍待实施。

## 5. M2：姿势资产与工程保存

- [x] M2-02 实现独立姿势草稿和姿势资产快照隔离；加载后编辑不会悄悄改写已保存资产。
- [x] M2-03 实现单姿势 JSON 导入/导出及骨架标识、版本兼容校验。

- [x] M2-05 串行化保存请求并使用工程修订号，避免旧保存覆盖新编辑。
- [x] M2-06 实现 `.motionforge` 工程导入/导出，采用 ZIP 内的 `project.json` 与 `assets/`。
- [x] M2-07 加入文件版本检查、迁移入口和导入失败处理；未知高版本拒绝载入，不覆盖当前工程。
- [x] M2-08 实现新建/打开时的未保存处理和本地存储失败后的下载备份通道。
- [x] M2-09 验证工程往返、刷新恢复、错误文件和存储失败恢复。

### 验收

保存三个不同姿势后刷新页面，姿势与草稿仍可恢复；导出工程并在干净浏览器环境导入后，骨架、姿势和参数一致且可继续编辑；损坏文件不能破坏当前工程；自动保存失败时仍可导出备份。

此阶段开始，后续新增的序列与参考图片也必须进入同一工程保存流程，不另建重复的权威数据源。

## 6. M3：时间轴与序列预览

### 任务

- [x] M3-01 实现动作序列的新建、命名、切换和删除，并纳入工程保存。
- [x] M3-02 支持将当前姿势或姿势资产作为独立快照插入时间轴。
- [x] M3-03 实现关键姿势新增、复制、删除、重命名、拖动排序和另存为姿势。
- [x] M3-04 实现持续帧数数字输入、拖动右边缘调整及按时长显示块宽度。
- [x] M3-05 实现帧区间计算、帧到关键姿势的定位、实际帧刻度及总时长显示。
- [x] M3-06 实现播放/暂停、循环、实际帧步进、关键姿势跳转和播放头拖动。
- [x] M3-07 以单调时钟计算播放帧，正确处理末尾、恢复播放、修改 FPS 和页面隐藏。
- [x] M3-08 实现草稿/序列编辑状态切换，播放期间锁定骨架编辑，播放头定位后编辑对应整段。
- [x] M3-09 实现前后关键姿势洋葱皮及透明度调整。
- [x] M3-10 所有序列编辑接入撤销重做与自动保存，并处理删除/缩短段后的播放头范围。

### 验收

固定示例 A×3、B×2、C×4 在 12 FPS 下严格对应 9 个播放帧、0.75 秒，逐帧得到 `A A A B B C C C C`。改为 24 FPS 后仍是 9 帧，总时长变为 0.375 秒。

编辑 B 段任意一个播放帧会修改整个 B 段；姿势库原资产不受影响。删除最后一段进入空序列；非循环播放停在最后一帧，再次播放从第一帧开始；循环无额外帧。保存并重开后段顺序、时长和骨骼数据保持一致。

## 7. M4：动作图导出与辅助编辑

### 任务

- [ ] M4-01 建立画布与导出共用的姿势绘制描述，输出不依赖视口变换。
- [ ] M4-02 实现当前姿势 PNG 导出、透明/纯色背景选择和最终图预览。
- [ ] M4-03 实现关键姿势图包：每段一张 PNG，附带 FPS、区间与持续帧数描述文件。
- [ ] M4-04 实现实际帧图包：按整数帧展开，使用补零连续文件名，附带总帧数、尺寸与顺序。
- [ ] M4-05 实现批量导出进度、取消、临时资源释放及像素量/内存预算检查。
- [ ] M4-06 实现本地参考图导入、移动、缩放、透明度、显隐和删除；图片随工程备份往返保存。
- [ ] M4-07 默认不导出参考图，可显式勾选；导出始终隐藏网格、选择框、洋葱皮和 IK 手柄。
- [ ] M4-08 实现脚部固定与根节点移动的联动，不可达时显示误差。
- [ ] M4-09 实现项目级基础骨架比例调整：更新所有姿势的骨架版本与辅助控制器、清理缩略图缓存，整个操作可一次撤销。
- [ ] M4-10 提供基本骨段前后显示顺序调整，帮助表达侧面及交叉肢体。

### 验收

固定示例输出 3 张关键姿势图或 9 张实际帧图；PNG 顺序、尺寸、背景及描述文件正确，重复帧保持相同姿势；画布缩放和平移不改变导出结果；取消导出不会清空工程。参考图和骨架比例修改可保存、重新读取并继续编辑。

导出的动作图可由用户正常打开并手动选择上传。本阶段不把第三方 AI 生图效果作为本工具的验收条件。

### 完成标准

用户可以从空工程独立完成摆姿势、保存、动作编排、预览、导出，再重新打开工程继续修改。核心数学和时长测试通过；无已知的数据丢失、工程损坏、关键帧错位或错误导出问题。

性能目标沿用产品方案：单角色不超过 40 根骨骼、单序列不超过 300 个关键姿势、总播放帧数不超过 3000；默认骨架拖动争取稳定 60 FPS。这些是待测目标；批量导出还需按图片尺寸限制，不能将 3000 帧直接视为任意尺寸下的导出保证。

## 9. 验证安排与风险处理

| 风险 | 最早验证阶段 | 处理方式 |
| --- | --- | --- |
| IK 极限位置抖动或翻转 | M1 | 数学边界用例、容差、上一有效方向、明确弯曲侧 |
| 多处保存骨骼坐标导致不一致 | M0–M1 | 以局部旋转为权威数据，世界位置由 FK 推导 |
| 草稿、姿势资产与序列互相污染 | M2–M3 | 深拷贝快照、编辑目标显式化、隔离验证 |
| 关键姿势数量与播放帧数混淆 | M3 | 两种计数分别显示，固定 3/2/4 示例贯穿测试 |
| 自动保存失败或旧写入覆盖新状态 | M2 | 串行提交、修订号、失败提示和下载备份 |
| 工程版本变化后无法读取 | M2 | schemaVersion、迁移入口、未知版本拒绝覆盖 |
| 骨架比例修改破坏已有姿势 | M4 | 全工程同步更新、重建控制器和一次撤销 |
| 大图包导致内存耗尽 | M4 | 逐帧处理、预算限制、进度和取消；必要时降低允许导出规模 |
| 编辑预览与导出图片不一致 | M4 | 共用帧采样和绘制描述，固定尺寸视觉检查 |

测试集中在数学边界、数据往返、时长规则和真实用户流程，不为纯布局或文案变更编写与实现重复的测试。每个阶段通过必要检查后继续推进，出现新问题再扩大验证范围。

## 10. 执行与变更规则

1. 每次开发围绕一个可验证任务或连续的小任务展开，完成后更新本文件复选框。
2. 标记完成须同时满足实现、对应验收和必要文档更新；仅创建页面或空函数不能算完成。
3. 若实现中调整数据格式或行为，同步修改产品方案，保证方案、计划和程序一致。
4. 界面使用中文，明确区分“保存可编辑数据”和“导出图片”。
5. 首版之外的补间、视频/GIF、蒙皮、多角色与任意骨架单独记录，不挤占当前阶段。
6. AI 接入不进入任务列表；用户始终自行处理外部生图流程。

下一步开发入口：进入 M4，实现当前姿势 PNG、关键姿势图包与实际帧图包，再接入参考图及辅助编辑。M3 结果详见 [开发记录](./开发记录-M3.md)。
