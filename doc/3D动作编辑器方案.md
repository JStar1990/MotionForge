# MotionForge：3D 假人动作编辑器产品与技术方案

版本：v0.4 · 2026-10-28。状态：双摄像机和基础 FK 已实现，其余按开发计划推进。

本方案替代原 2D 路线。当前程序提供独立 3D 编辑入口并保留 2D 原型；已完成的 2D 功能不等于下述 3D 功能已完成。旧设计、阶段验收与开发计划保留在 archive 和 M0～M4 记录中。

## 1. 目标与范围

在真实 3D 空间操纵一个带骨骼和蒙皮的中性人体假人，使用自由摄像机观察与编辑，用独立的固定截图摄像机生成一致取景的动作参考图。解决双臂前伸、朝镜头出拳、肩胯扭转、肢体前后交叉等平面骨架难以表达的动作。

首版仍为本地浏览器应用、单角色、手动 IK/FK 摆姿势、姿势库和保持式关键姿势序列。保留工程备份、自动保存、撤销重做、PNG 与帧图包。默认 1024×1024、12 FPS、新段持续 2 帧。不同姿势之间不自动补间。

不加入建模、重拓扑、蒙皮权重绘制、布料、物理、多人场景、自动动作生成或任意骨架重定向。使用已有模型的蒙皮是必需能力，编辑蒙皮权重不属于首版。保留手指骨骼，但首版以整只手朝向为主。AI 生图仍由用户在外部工具手动完成，不添加 AI 接口或自动上传。

## 2. 双摄像机：编辑与截图明确分离

| 项目 | 自由摄像机（编辑） | 截图摄像机（输出） |
| --- | --- | --- |
| 用途 | 观察遮挡、检查纵深、拾取与调整人物 | 固定构图、预览和输出关键动作帧 |
| 默认投影 | 透视，可切正交辅助视图 | 正交，可显式切换透视表现近大远小 |
| 交互 | 环绕、平移、拉近拉远；正/背/左/右/顶快捷视图 | 默认锁定，仅在“调整截图摄像机”模式可操作 |
| 与人物关系 | 可手动聚焦选中关节 | 固定世界坐标，不自动跟随人物或随姿势适配 |
| 保存位置 | 本机编辑器偏好，按工程记忆；不属于姿势历史 | 工程权威数据，参与撤销、自动保存和备份 |
| 导出权威 | 不参与导出 | 唯一导出摄像机 |

中央为自由视图，右侧提供持续更新的截图预览窗，始终标明“截图摄像机”。预览保持输出宽高比，空白区域用留边表达，不能因预览窗尺寸改变截图构图。自由视图显示截图摄像机位置/朝向与视锥，辅助线不出现在最终图中。

截图摄像机支持世界位置 XYZ、朝向（界面角度/目标点工具）、正交视野高度或透视 FOV、近远裁剪面和输出宽高设置。旋转内部使用四元数作为唯一权威，目标点只作为调节工具，不再保存一份可能冲突的 lookAt。

提供“采用当前自由视角”和“在自由视图查看截图机”两个明确按钮；前者执行一次复制命令，不建立持续绑定。调整后点击“锁定截图机”。鼠标继续操作自由视图不得改变截图机。截图机位置、姿态、投影及尺寸变化均使缩略图缓存失效。

同一工程所有动作默认共用一台截图机；首版不支持每关键姿势的相机关键帧。用户调整截图机后重新导出的所有帧使用新构图，已下载的图片不会被修改。保存姿势只保存骨骼快照，不把自由摄像机或截图机藏入姿势数据。

## 3. 人体模型与空间约定

使用 Quaternius Universal Base Characters Standard 中带 Humanoid 骨骼的 Superhero 男性素体作为首个接入候选，女性素体作为备用。来源与实际下载文件清单见 [模型资产记录](../assets/models/quaternius/README.md)。作者标注 CC0；原始许可与模型一起保留。它是类似 UE 假人用途的第三方人体素体，不是 Epic 官方 Manny/Quinn，也不假定骨架与 UE 完全一致。

呈现为中性灰材质，清晰表现人体体积、关节及前后遮挡。导入时保留原始 mesh、skin、骨骼名称、绑定矩阵、静止姿态；展示材质可覆盖，不改写下载原件。隐藏头发、服装和其他非必要附件。先验证肩/肘/髋变形，再决定是否作为正式默认资产；不能只因带骨架就宣称 IK 可直接工作。

运行时统一使用 glTF 2.0/GLB。资源身份由内容哈希和固定资源路径确定，模型不跟随每个姿势重复保存。模型缺失、损坏或骨架不匹配时给出提示，保留工程数据，不静默换模型。

空间采用右手系、米制、Y 向上、XZ 为地面；规范化后人物面向 +Z，角色自身左侧为 +X。世界原点位于默认站立位置的地面中心，角色根变换与骨盆关节分开。导入校正通过独立 assetTransform 完成，先验证原单位、面向及根节点，禁止把 FBX/UE 的厘米或 Z-up 假定直接套到 glTF。

## 4. 3D 骨架与操作

骨骼状态以根节点平移/旋转及局部旋转四元数为权威，世界矩阵由 FK 推导；保持原绑定平移与缩放。不要保存第二套“世界关节点坐标”作为权威。Euler 角只供属性面板显示/输入，规范化四元数，拒绝 NaN、零四元数与无效缩放。

建立版本化语义映射：root、pelvis、spine、chest、neck、head、左右 clavicle、upperArm、forearm、hand、thigh、shin、foot；需要检查中间骨、扭转骨和辅助骨，不凭数组下标或相似名字猜测。模型原始骨架可以多于 40 根，交互控制数量与模型骨骼数分开统计。

| 操作 | 行为 |
| --- | --- |
| 拖手腕/脚踝 IK 控制器 | 在选定平面/轴上移动目标，求解两段肢体，骨长不变 |
| 拖肘膝 pole target | 在 3D 空间指定弯曲平面，支持前后深度 |
| FK 旋转环 | 调整局部或世界轴旋转；手掌/脚掌独立定向 |
| 根节点变换 | 移动/旋转整个人物；固定脚保持世界目标 |
| 正/侧/顶快捷视图 | 改变自由摄像机，便于消除深度歧义 |
| 数值 XYZ/角度输入 | 精确调整目标、根节点或旋转 |

默认拖动在穿过被选目标、平行当前视图的平面上进行；提供 XY/XZ/YZ 和单轴约束，切换时明确显示平面。禁止从二维鼠标位置同时猜测三个空间坐标。拖动骨骼时暂停相机控制，释放后恢复；Esc 取消，一次拖动一条历史。

IK 用肩/髋起点、两段骨长、世界目标与 pole target 定义。处理目标不可达、全伸直、折叠、pole 共线与根节点旋转，保留上一稳定弯曲平面。关节限制按骨骼局部轴定义 swing/twist 或铰链范围，不复用 2D 单角度限制。IK/FK 切换先从当前姿势初始化目标，避免跳姿势。播放直接应用保存的旋转，不每帧重新求解。

固定脚以世界空间目标保存，移动根节点后解腿部；不可达时显示误差，不拉长骨骼。左右/深度遮挡由深度缓冲解决，停止原 2D 手工绘制顺序功能。体型比例需要模型/蒙皮适配，暂不将任意骨长修改带入首个 3D 版本。

### 4.1 直接摆动骨骼的交互优先级

自由视图提供可点击的主要关节点，选中后高亮并显示旋转环，骨骼列表同步选择。用户拖动局部 XYZ 旋转环即可摆动对应身体部位，后代骨骼与蒙皮实时跟随，截图摄像机实时显示同一姿势。数值输入用于精调，不作为唯一编辑入口。

旋转环优先于关节点拾取；关节点可透过素体显示，辅助控件支持隐藏。拖动旋转环期间暂停自由相机，一次拖动仅提交一次撤销记录；Esc 取消且恢复原姿势。骨骼选择、显示开关不会修改姿势，也不会改变截图。关节点、旋转环及后续骨架连线均属于编辑辅助层，截图预览和正式输出必须排除。

已接入直接 FK、骨架连线、世界轴切换和基础手脚 IK；关节限制与肘膝方向控件仍待完成。关节约束加入前应在界面说明可能出现不自然的关节角度。

### 4.2 平移拖拽

提供“旋转骨骼（FK）”和“平移手脚（IK）”两种操作模式。平移模式选择左右手或脚，拖轴箭头、平面方块或中心控件移动目标，控制目标与实际骨骼分离。两段肢体通过旋转跟随目标，保留绑定位置、缩放和骨长，保持手脚原世界朝向。非手脚关节在此模式下提示选择手脚，不显示误导性的平移控件。

基础版使用当前弯曲方向，伸直时使用稳定默认方向；超出肢体范围时提示并停在可达位置。后续补充显式肘膝方向目标与解剖关节限制。切换模式不得跳姿势，一次拖拽的多骨骼变化作为同一个撤销命令，Esc 取消全部变化。

整个人物平移作为独立根节点控件实现，后续与固定脚、保存恢复联动。默认姿势编辑不开放普通骨骼绑定位置修改，以免拉长肢体或改变素体结构。

## 5. 关键姿势、截图与时间轴

沿用 PoseAsset 与 KeyPose 的独立快照关系，以及 durationFrames 正整数时长。A×3/B×2/C×4 严格对应 AAABBCCCC，12 FPS 为 0.75 秒，24 FPS 为 0.375 秒。编辑段内任意一帧影响整段，草稿不受影响；所有编辑参与撤销和保存。

区分两个按钮：“保存关键姿势”写入可编辑骨骼数据；“截图当前姿势”从截图摄像机渲染并下载 PNG。关键姿势缩略图使用同一截图机生成，是可重建缓存。相机变化后统一重建，避免旧缩略图与当前输出混淆。

自由视图可显示前后关键姿势的半透明 3D 骨架，截图默认排除。非循环末尾停止、循环、逐帧、段跳转、修改 FPS 暂停、页面隐藏暂停等规则不变。

## 6. 渲染与导出

Three.js 场景包含带蒙皮假人、固定灯光、中性背景、可选地面。灯光采用工程/场景固定参数，不跟随自由摄像机，避免环绕观察导致截图光照变化。自由视图与截图视图读取相同姿势、场景参数和材质；只有相机及辅助层不同。

输出由专用渲染目标和截图摄像机产生，不能读取自由视图截图。读取实际像素时处理 WebGL Y 翻转、色彩空间、透明 alpha、抗锯齿和宽高比；不随窗口大小、DPR 或自由视口变化。导出前冻结项目修订、模型版本、相机与灯光设置，使用独立姿势实例逐帧渲染，不改变正在编辑的场景。

支持当前 PNG、每关键姿势 PNG 包、实际播放帧 PNG 包。图包 manifest 记录格式版本、坐标约定、模型哈希、截图机参数、FPS、尺寸、背景、帧区间和顺序；重复帧复用 PNG 数据。默认透明背景，可选纯色；网格、控制器、相机视锥、骨骼选择和洋葱皮始终排除。是否输出骨架线/地面阴影须为明确导出选项。

保留取消、进度、像素预算和字节预算；原 2D 的限额仅作为起始上限，3D 要额外核算渲染目标、深度、MSAA、模型与纹理显存，不直接承诺旧限额。查询设备能力，处理 WebGL 上下文丢失与 GPU 不可用；失败不清空工程。批量资源及时 dispose。

## 7. 技术结构

保留 React、TypeScript、Vite、Zustand、Dexie、Zod、JSZip、Vitest、Playwright。新建 Three.js 渲染层，使用 GLTFLoader 加载、OrbitControls 操纵自由机、TransformControls 作为变换交互基础。TransformControls 不负责 IK；IK 和操作平面由核心与控制器层实现。此阶段不引入 UE 编辑器或打包 UE 运行时。

先采用直接 Three.js 集成：React 管面板，SceneController 管渲染器、模型、相机和控制器生命周期，避免同时加入多个 3D 状态来源。Three.js 版本在实现阶段核对并锁定。Konva 保留给旧 2D 工程，不承担新的 3D 人物渲染。

建议新增 core/rig3d、core/project3d、editor/scene3d、export/render3d；复用通用时间轴数学、命令历史与存储队列，避免在全部旧模块上直接替换类型。运行时 Three.js 对象不写入 Zustand 工程快照。

## 8. 数据版本与兼容

新工程 schemaVersion=2、dimension='3d'；旧工程 schemaVersion=1 的 2D 数据保持原样，可通过旧编辑器打开和导出。没有真实深度信息的旧姿势不自动转换为等价 3D。新建工程以后默认走 3D；如用户需迁移，后续提供“作为二维参考图”流程，不宣称无损转成 3D。

核心结构草案（是待实现设计，不是现有校验器已支持的格式）：

```ts
type Vec3 = [number, number, number];
type Quat = [number, number, number, number]; // x,y,z,w, normalized
interface Camera3D {
  position: Vec3;
  rotation: Quat;
  projection: 'orthographic' | 'perspective';
  orthoHeight: number;
  fovDegrees: number;
  near: number;
  far: number;
}
interface Pose3D {
  rigId: string;
  rigRevision: number;
  rootPosition: Vec3;
  rootRotation: Quat;
  localRotations: Record<string, Quat>; // bindRotation * delta
  ikControls: Record<string, {
    target: Vec3; pole: Vec3; mode: 'ik' | 'fk'; pinned: boolean;
  }>;
}
interface Project3D {
  schemaVersion: 2;
  dimension: '3d';
  id: string; name: string; revision: number;
  model: { assetId: string; sha256: string; rigId: string; mappingVersion: number };
  rig: { id: string; revision: number; boneMap: Record<string, string> };
  assetTransform: { position: Vec3; rotation: Quat; scale: number };
  captureCamera: Camera3D; // 独立于姿势和自由机
  output: { width: number; height: number; background: string | null };
  sceneStyle: { materialPreset: string; lightingPreset: string; showGround: boolean };
  fps: number; defaultDurationFrames: number;
  draft: Pose3D;
  poses: Array<{ id: string; name: string; pose: Pose3D }>;
  clips: Array<{ id: string; name: string; keys: Array<{
    id: string; name: string; pose: Pose3D; durationFrames: number;
  }> }>;
}
```

绑定骨架从经哈希校验的模型读取，语义映射带版本；骨骼 ID 以稳定路径或导入映射生成，重复名称不能作为唯一键。工程 ZIP 包含使用到的 GLB、纹理与许可，默认模型允许按内容去重但备份必须可离线恢复。摄像机验证 near>0、far>near、非退化旋转、有效 FOV/orthoHeight，所有坐标有限。高版本拒绝覆盖当前工程。

## 9. 核心验收

1. 双臂前伸：侧面自由视图能看到两臂真实纵深，截图机正面能看到透视缩短/遮挡。
2. 朝镜头出拳：透视截图下近手更大，正交下保持一致比例；没有 2D 手工缩短骨长。
3. 弓步扭身：肩胯可独立旋转，肘膝不翻转，蒙皮无明显破裂。
4. 自由机环绕、缩放、移动后，相同姿势的截图构图/像素在同一设备设置下不变。
5. 截图机解锁调整→锁定→刷新/备份恢复后，相机参数与输出一致；调整可撤销。
6. 3/2/4 序列得到 3 张关键姿势图或 9 张实际帧图，全程使用同一截图机。
7. 旧 schemaVersion=1 工程可继续打开，新旧导入错误均不能覆盖当前工程。
