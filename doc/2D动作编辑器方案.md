# MotionForge：2D 动作编辑器产品与技术方案

版本：v0.2 · 2026-10-26

## 1. 目标与已确认范围

制作一个专注于动作本身的 2D 编辑器：用户通过带 IK 的骨骼摆出姿势，将姿势保存为单张动作，或组织成可以播放的动作序列。序列中的每个关键姿势可以持续一个或多个实际播放帧。

工具定位为以手动操作为主的纯 2D 动作编辑器，不加入 3D 骨骼、相机或深度编辑。用户在工具内完成摆姿势、编排动作、预览和导出，再自行将动作图发送到其他 AI 工具进行生图。

AI 生图属于工具外部的手动流程，不属于本项目功能范围。项目不提供 AI 接口、服务适配层、生成任务队列、密钥配置、提示词编辑、生成按钮、自动上传或结果回传，也不将 AI 接入列入后续开发路线。IK 求解、本地自动保存和序列播放仍作为手动编辑的辅助能力保留。

建议默认参数：单角色人体骨架、1024 × 1024 画布、12 FPS、新关键姿势持续 2 帧。这些是可修改的产品默认值，不是固定限制。

## 2. 核心概念与时间规则

| 概念 | 含义 |
| --- | --- |
| 骨架 Rig | 骨骼层级、长度、默认方向、关节限制和 IK 链定义 |
| 姿势 Pose | 某一时刻根节点的位置及各骨骼局部旋转，附带编辑控制器状态 |
| 姿势资产 | 独立保存、可反复插入序列的姿势快照 |
| 关键姿势 KeyPose | 时间轴上的一个姿势快照及其持续帧数 |
| 播放帧 Frame | 按项目 FPS 播放的实际时间单位 |
| 动作序列 Clip | 有顺序的关键姿势列表 |

### 2.1 关键姿势采用“曝光时长”模型

用户保存的是关键姿势，不需要把重复播放的每一帧都手动保存。每个关键姿势具有正整数 `durationFrames`，默认播放方式为保持姿势，直到下一个关键姿势开始。

示例：FPS = 12。

| 关键姿势 | 持续帧数 | 实际播放帧（界面从 1 开始） | 占用时间 |
| --- | --- | --- | --- |
| A：准备 | 3 | 1–3 | 0.250 秒 |
| B：出手 | 2 | 4–5 | 约 0.167 秒 |
| C：收势 | 4 | 6–9 | 约 0.333 秒 |

该序列有 3 个关键姿势、9 个播放帧，总时长为 0.75 秒。播放内容为 `A A A B B C C C C`。这是本期唯一的播放模式，不默认补间。

规则：

- `总帧数 = Σ durationFrames`；`总时长秒 = 总帧数 / FPS`。
- 数据内部帧索引从 0 开始；界面从 1 开始。每段区间是左闭右开，例如 A 对应内部 `[0, 3)`。
- 修改 FPS 保持持续帧数不变，因此改变整体播放速度；界面同步显示新总时长。
- 修改某段持续帧数，后续段整体顺延或前移。本期不支持时间轴空洞、段重叠或多轨合成。
- 关键姿势之间不生成隐藏中间帧。以后若加入补间，必须单独定义过渡段和占用时间，不能改变现有“保持”语义。
- 修改某段覆盖范围内的姿势，会修改整个关键姿势段，界面明确显示正在编辑的段名。

### 2.2 单姿势与序列之间的关系

“保存姿势”保存可编辑数据和缩略图；“导出姿势图”导出 PNG，两者是不同操作。

从姿势库插入时间轴时复制快照，后续修改姿势库或序列中的副本互不影响。用户可将序列中的任意关键姿势另存为姿势资产。

## 3. 编辑器布局与操作流程

### 3.1 布局

- 顶部：新建、打开、保存备份、撤销、重做、导出。
- 左侧：骨骼树、姿势库、参考图片。
- 中央：2D 画布，显示骨骼、关节、IK 控制点、地面参考线及可选洋葱皮。
- 右侧：当前选择的属性，包括位置、角度、IK 弯曲方向；选中关键姿势时显示名称和持续帧数。
- 底部：关键姿势时间轴、播放头、播放/暂停、逐帧前后移动、FPS、循环播放及总时长。

### 3.2 单姿势流程

1. 新建项目，加载默认人体骨架。
2. 在画布拖动手脚 IK 控制点，旋转躯干、头部或骨骼，摆出姿势。
3. 点击“保存为姿势”，输入名称并进入姿势库。
4. 可导出透明或纯色背景 PNG，也可将姿势加入序列。
5. 需要生图时，用户自行打开其他 AI 工具并手动上传导出的动作图；本编辑器不参与上传和生成。

### 3.3 序列流程

1. 将当前姿势加入序列，指定持续帧数。
2. 复制上一关键姿势，调整骨骼形成下一姿势。
3. 修改各段时长、拖动排序，播放检查节奏。
4. 开启前后关键姿势洋葱皮，检查位移和动作连贯性。
5. 保存工程，导出关键姿势图包或实际帧序列及描述文件。
6. 需要在其他 AI 工具中生图时，用户自行解压图包、选择动作图并手动上传。

### 3.4 编辑状态

画布明确区分“独立姿势草稿”和“正在编辑序列第 N 段”。独立草稿在切换到时间轴时保留；编辑序列时，拖动结束即提交到所选段，支持撤销。

点击播放前先提交当前拖动；播放期间禁止改动骨骼，暂停后恢复编辑。拖动播放头会暂停播放，并选择该帧所在的关键姿势段。

## 4. 2D 骨架与 IK

### 4.1 默认人体骨架

采用单根树状结构：根节点位于骨盆，连接躯干和双腿；躯干连接颈部、头部、左右肩膀和双臂。左右手、左右脚分别作为四条 IK 链的末端。

默认骨段包括骨盆/躯干、颈部/头部、左右肩部连接段、左右上臂/前臂/手部、左右大腿/小腿/脚部。手脚的小段主要用来调整朝向，不进入两段 IK 求解。

保留明确的左右命名。侧面动作可通过画布内位置、弯曲方向和骨段前后显示顺序表达；不推断被遮挡肢体的真实深度。

### 4.2 操作模式

| 操作 | 结果 |
| --- | --- |
| 拖动手腕/脚踝控制点 | 使用两段 IK 带动对应上、下肢 |
| 拖动肘/膝方向控制柄或点击翻转 | 改变 IK 弯曲侧 |
| 拖动根节点 | 平移整个角色 |
| 旋转骨骼 | FK 旋转，后代随父级变化 |
| 旋转手掌/脚掌 | 只调整末端方向 |
| 重置姿势 | 恢复默认姿势，保留骨架比例 |

IK/FK 在选中肢体上切换。切换时先根据当前姿势初始化目标点和弯曲方向，避免姿势跳变。普通根节点移动会同时移动 IK 目标；开启脚部固定时，固定脚的目标留在画布坐标中，重新求解腿部。

### 4.3 约束与边界

- 骨长默认固定，拖动时不拉长肢体。
- IK 目标不可达时，末端停在可达范围，并显示目标点与实际末端的偏差。
- 肘、膝允许配置角度限制；镜像后的左右限制必须正确映射。
- 目标接近链起点、两骨段长度相同且折叠、完全伸直等情况，要用容差和上一有效方向处理，避免除零及抖动。
- 脚部固定是编辑辅助约束。本期为保持帧播放，不承诺运动中的自动足底接触或物理模拟。
- 修改骨架比例属于项目级操作，会影响所有姿势。首版仅提供统一骨架和基础比例设置；已有动作时需明确展示影响，并允许撤销整个修改。
- 多角色、自定义任意骨架、手指骨骼、蒙皮变形、布料和物理不在本期范围。

## 5. 时间轴细节

时间轴分为关键姿势块和实际帧刻度。姿势块宽度按持续帧数成比例显示，块内有缩略图、名称及“×3 帧”等时长提示；缩小时保留选中块的文字信息。

支持新增、复制、删除、拖动排序，以及通过右侧数字输入或拖动块右边缘修改持续帧数，最小为 1。复制后插入原段之后，创建独立姿势快照。删除最后一段后进入空序列状态，禁止播放并提供“添加当前姿势”。

逐帧按钮按实际播放帧移动；另设“上一个/下一个关键姿势”，避免把这两种跳转混淆。洋葱皮显示前后关键姿势，而不是相同姿势的相邻重复播放帧。

非循环播放到末尾后停留在最后一帧；再次播放从第一帧开始。循环播放默认直接从最后一段切回第一段，不自动产生过渡。

## 6. 保存和导出

### 6.1 保存内容

工程包括画布尺寸、背景设置、FPS、骨架定义、姿势库、动作序列及引用图片。编辑器偏好（面板尺寸等）与工程数据分开保存。

- 自动保存：本地数据库保存编辑结果，操作提交后防抖写入，并显示“已保存/保存中/保存失败”。
- 工程备份：下载 `.motionforge` 文件，采用 ZIP 容器，包含 `project.json` 和 `assets/`。可在另一浏览器或电脑重新打开。
- 单姿势文件：JSON 数据，带骨架标识与版本；跨不同骨架导入时拒绝直接套用，并解释不匹配原因。本期不做自动重定向。
- 浏览器本地存储可能被清除，自动保存不能替代工程备份。写入失败保留内存工作状态，允许立即下载备份。

### 6.2 图像导出

| 导出项 | 行为 |
| --- | --- |
| 当前姿势 PNG | 按项目画布尺寸导出，背景可选透明或纯色 |
| 关键姿势 PNG 包 | 每个关键姿势一张图，描述文件保留各自持续帧数 |
| 实际帧 PNG 包 | 按播放帧展开，重复姿势也输出对应帧文件 |
| 工程备份 | 保留可继续编辑的全部工程数据 |

例如 A×3、B×2、C×4：关键姿势包为 3 张图，实际帧包为 9 张图，二者的描述文件都记录 FPS、总帧数、尺寸、顺序与关键姿势区间。

导出图片默认隐藏网格、选择框、IK 手柄及洋葱皮，只显示骨架动作图。参考图片默认不导出，可显式勾选。导出不受当前视口缩放和平移影响，不自动逐帧裁切，以保持角色位置一致。

本期不导出视频、GIF 或精灵图集；可在后续独立增加。内部序列预览已经覆盖本期动作检查需求。

### 6.3 外部工具的手动使用流程

导出前可预览最终动作图，确认画布尺寸、背景、骨架可见性和参考图片是否包含在内。单姿势下载 PNG；多个动作下载 ZIP，内部图片按顺序命名，便于解压后选择和上传。

工具的工作流程到文件下载为止。用户在其他 AI 工具中自行选择模型、填写提示词、上传动作图并保存生成结果。本项目不承诺外部工具会严格遵循姿势；导出的动作图是通用视觉参考，不声明符合某个模型专用的姿势控制协议。可编辑骨骼数据继续保存在工程中，方便用户调整后重新导出。

## 7. 推荐技术实现

### 7.1 选型结论

先做浏览器本地运行的单页应用：**React + TypeScript + Vite + Konva/react-konva + Zustand + Dexie**。无需业务后端即可完成本期编辑、存储和导出。

这是面向少量骨骼、复杂交互的编辑器选型。Konva 用于画布节点与交互，DOM 用于面板和时间轴；无需引入游戏引擎或 3D 引擎。

| 层 | 建议 | 作用与边界 |
| --- | --- | --- |
| UI | React + TypeScript | 属性面板、资源列表、时间轴、类型约束 |
| 构建 | Vite | 本地开发和静态构建，实际依赖版本在初始化时锁定 |
| 画布 | Konva + react-konva | 骨段、关节、手柄、参考图、拾取与拖动 |
| 骨骼核心 | 纯 TypeScript 模块 | FK、两段 IK、约束、坐标转换，与 UI 解耦 |
| 状态 | Zustand | 工程状态、选择状态、播放状态分开管理 |
| 本地数据 | IndexedDB + Dexie | 工程快照、图片 Blob、缩略图及版本迁移 |
| 文件校验 | Zod | 工程导入的结构、数值范围与版本校验 |
| 打包导出 | JSZip + Canvas PNG 编码 | 工程与帧图片打包下载，导出过程显示进度 |
| 自动验证 | Vitest + Playwright | 数学/时间规则单测和关键用户流程验证 |

Zustand 的轻量持久化仅用于界面偏好，工程以 Dexie 为唯一持久化入口，避免多份数据互相覆盖。Konva 的通用 Transformer 不负责 IK；骨骼旋转和 IK 手柄需要自定义交互。

### 7.2 模块边界

```text
src/
  core/
    rig/           骨架定义、局部/世界变换、FK、IK、约束
    animation/     段区间、帧采样、播放时钟
    project/       数据模型、校验、迁移
    commands/      编辑命令与撤销/重做
  editor/
    canvas/        画布渲染、拾取、坐标转换、拖动
    timeline/      关键姿势块、播放头、时长编辑
    panels/        属性、姿势库、骨骼树
    state/         工程状态与临时 UI 状态
  persistence/     IndexedDB、工程文件读写
  export/          统一动作图渲染、PNG、ZIP、描述文件
```

核心模块只接受数据并返回数据，不依赖 React、Konva 或数据库。画布显示和导出使用同一份帧采样与绘制描述，避免预览和导出的姿势不同。

### 7.3 坐标与骨骼表示

统一项目坐标：画布左上为原点，X 向右、Y 向下，单位为项目像素。存储角度使用弧度，面板显示角度。

骨架保存骨骼父子关系、长度、在父节点坐标系中的连接偏移以及静止角；姿势保存根节点位置/角度和各骨骼相对静止角的局部旋转增量。世界关节位置全部由 FK 推导，不再保存第二套权威位置数据。

屏幕输入先通过视口逆变换转成项目坐标，再参与 IK。缩放、平移和设备像素比例不参与骨骼数学计算。

### 7.4 两段 IK 实现

人体四肢优先使用解析式两段 IK：一个肩/髋起点、两段固定骨长、一个手腕/脚踝目标，以及一个弯曲侧标记。比通用迭代求解器更便于处理本期固定结构。

设起点为 R、目标为 T、骨长为 L1 和 L2：

1. 计算目标距离 `d = |T - R|`；将求解距离限制在 `[|L1-L2|+ε, L1+L2-ε]`，对极短骨长另做合法性限制。
2. 计算目标方向 `φ = atan2(Ty-Ry, Tx-Rx)`；零距离使用上一有效方向。
3. 计算 `α = acos(clamp((L1²+d²-L2²)/(2L1d), -1, 1))`。
4. 按弯曲侧 `s ∈ {-1, 1}` 得到上段方向 `φ+sα`，求出肘/膝位置，再求下段方向。
5. 将世界方向转换成父骨骼空间的局部旋转增量，经过 FK 重建结果。

上述解析式解决不受角度限制的链。加入关节限制时，先检查解析解；若超限，在允许角度范围内执行有界修正，选择末端误差较小且弯曲方向连续的解。不能仅夹取角度后声称目标已到达。受限后的实际末端位置由 FK 重算并显示偏差。

保存时以求解后的局部旋转为显示依据；IK 目标、弯曲方向和固定状态作为恢复编辑的辅助数据。播放时直接采样已保存姿势，不重新求解造成漂移。

### 7.5 数据结构草案

```ts
type Vec2 = { x: number; y: number };

interface BoneDefinition {
  id: string;
  parentId: string | null;
  offset: Vec2;              // 父骨骼局部坐标中的连接位置
  length: number;
  restAngle: number;
  angleLimit?: { min: number; max: number }; // 局部旋转增量范围
}

interface IKChain {
  id: string;
  upperBoneId: string;
  lowerBoneId: string;
}

interface RigDefinition {
  id: string;
  revision: number;
  bones: BoneDefinition[];
  ikChains: IKChain[];
  drawOrder: string[];
}

interface PoseSnapshot {
  rigId: string;
  rigRevision: number;
  rootPosition: Vec2;
  rootRotation: number;
  localRotations: Record<string, number>;
  ikControls: Record<string, {
    target: Vec2;
    bendSign: 1 | -1;
    mode: 'ik' | 'fk';
    pinned: boolean;
  }>;
}

interface PoseAsset {
  id: string;
  name: string;
  pose: PoseSnapshot;
}

interface KeyPose {
  id: string;
  name: string;
  pose: PoseSnapshot;        // 深拷贝快照，不引用姿势资产
  durationFrames: number;    // 必须为 >= 1 的整数
}

interface Clip {
  id: string;
  name: string;
  keys: KeyPose[];           // 起始帧由顺序和持续帧数派生
}

interface Project {
  schemaVersion: number;
  id: string;
  name: string;
  canvas: { width: number; height: number; background: string | null };
  fps: number;               // 首版限制为 1–60 的整数
  rig: RigDefinition;
  poses: PoseAsset[];
  clips: Clip[];
  referenceImages: Array<{
    assetId: string;
    position: Vec2;
    scale: number;
    opacity: number;
  }>;
}
```

图片二进制存入独立资产表，不嵌进每个姿势。缩略图为可重建缓存。导入时检查骨架无环、父节点存在、ID 唯一、数值有限、骨长有效、时长为正整数、姿势骨骼集合与骨架匹配；工程迁移需要统一更新姿势库和所有序列。

### 7.6 播放实现

使用 `requestAnimationFrame` 刷新视图，以单调时钟累计时间计算实际帧，避免每次回调简单加一造成播放速度随显示器刷新率变化。

```text
elapsedFrames = floor((now - startedAt) * fps / 1000)
absoluteFrame = startFrame + elapsedFrames
loopFrame = absoluteFrame % totalFrames
```

非循环模式将帧限制到 `totalFrames - 1` 并停止。暂停后记录当前帧，恢复时重置时钟起点；切换 FPS 时先暂停并保留当前帧。页面隐藏时自动暂停，避免回到页面突然跳过大量内容。

根据持续帧数构建段结束位置的前缀和，用二分查找定位当前关键姿势。重复播放帧可复用同一姿势渲染。导出按整数帧遍历，完全不依赖实时播放时钟。

### 7.7 撤销、保存与性能

- 一次拖动只形成一条撤销记录；拖动过程更新临时预览，松手后提交。取消拖动恢复起点。
- 新增、删除、排序、时长修改、骨架比例修改和姿势修改均纳入命令历史；播放和视口移动不进入工程撤销历史。
- 工程保存采用串行写入及修订号，防止较旧的异步保存覆盖新状态。工程文件导入先完整校验，再替换当前状态。
- 参考图、洋葱皮、骨架和操作辅助分层；播放时不重复生成缩略图或写数据库。
- 图片逐帧渲染、复用画布并释放临时资源，显示进度且支持取消。大导出设置像素量上限，避免浏览器内存耗尽。
- 首版目标规模：单角色不超过 40 根骨骼、单序列不超过 300 个关键姿势、总播放帧数不超过 3000。该规模是开发验证目标，实际导出还受尺寸及内存预算限制。

## 8. 实施顺序与验收

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| M1：骨架编辑 | 画布、人体骨架、FK、四肢 IK、根节点移动、撤销 | 手脚可拖动；骨长不变；不可达目标和极限折叠不会产生无效数值 |
| M2：姿势资产 | 保存/加载姿势、缩略图、本地保存、工程导入导出 | 重新打开工程恢复相同姿势；姿势副本互不影响 |
| M3：动作时间轴 | 关键姿势增删复制排序、持续帧数、播放、洋葱皮 | A×3/B×2/C×4 在 12 FPS 下播放 9 帧、0.75 秒；定位和循环边界准确 |
| M4：导出与打磨 | PNG、关键姿势包、实际帧包、参考图、脚固定及错误恢复 | 实际帧包包含正确顺序的 9 张图，尺寸/背景一致；导出不带编辑手柄 |

优先完成 M1–M3 的编辑闭环，再完成 M4。所有阶段围绕手动编辑、本地保存与文件导出展开。

必要验证：

1. IK：左右弯曲解、远近不可达、零距离、伸直、关节限制、父骨骼旋转后坐标正确。
2. 时间轴：单段、空序列、每段边界、非循环结束、循环回绕、FPS 修改和时长修改后的播放头裁剪。
3. 数据：导入导出往返一致；损坏文件和骨架不兼容有明确提示；撤销一次完整拖动。
4. 交互：缩放/平移后拖动仍准确；姿势入库和插入序列后修改互不影响；暂停后修改当前段正常。
5. 渲染：预览与导出的世界坐标一致；透明 PNG 的 alpha 正确；视口缩放不改变导出尺寸。

性能目标需在实际开发机器与常用浏览器上测量：默认骨架拖动争取稳定 60 FPS；目标规模下播放无明显停顿。文档中的性能目标不作为已验证结论。

## 9. 首版边界与后续扩展

首版必须完成：2D 人体骨架、四肢 IK/FK、姿势独立保存、关键姿势时间轴、每段持续多帧、序列预览、撤销重做、本地保存和工程/PNG 导出。

后续可分别讨论补间过渡、任意骨架、多角色、图片部件绑定、精灵图集和视频导出。本期不提前实现这些扩展的接口或页面。外部 AI 工具始终由用户手动使用，不纳入本项目开发路线。

本方案采用的默认决策为：浏览器本地应用、单角色人体骨架、保持式关键姿势播放、12 FPS、每段默认 2 帧。它们足以开始实现，后续可根据实际操作体验调整。
